## 🛠️ How Can I Contribute?

### 🐛 Reporting Bugs

Before creating an issue, please check existing [GitHub Issues](https://github.com/devmindstechnologies/react-native-dynamic-responsive/issues) to ensure it hasn't already been reported.

When submitting a bug report:
1. Use the **Bug Report** template.
2. Provide a minimal, reproducible code example.
3. Include your React Native and package versions.
4. Describe the expected vs. actual behavior.

### 💡 Suggesting Features

We welcome ideas that make responsive React Native development easier and cleaner!
1. Check the existing issues to ensure the feature hasn't been proposed yet.
2. Open an issue using the **Feature Request** template.
3. Clearly describe the problem you're solving and proposed API syntax.

### 🚀 Submitting Pull Requests

1. **Fork** the repository and clone it locally.
2. Create a new branch for your feature or fix:
   ```bash
   git checkout -b feature/my-new-feature
   ```
3. Make your changes in `src/`.
4. Ensure TypeScript compiles without errors:
   ```bash
   npm run build
   ```
5. Commit your changes with clear messages (see below).
6. Push your branch to GitHub and open a **Pull Request** against `main`.

## 💻 Development Setup

1. **Clone your fork**:
   ```bash
   git clone https://github.com/<your-username>/react-native-dynamic-responsive.git
   cd react-native-dynamic-responsive
   ```

2. **Install dependencies**:
   ```bash
   npm install
   ```

3. **Compile TypeScript**:
   ```bash
   npm run build
   ```

## 📝 Commit Message Guidelines

We follow standard conventional commit conventions:
- `feat:` A new feature
- `fix:` A bug fix
- `docs:` Documentation only changes
- `refactor:` Code changes that neither fix a bug nor add a feature
- `chore:` Changes to build process, tooling, or package configurations
